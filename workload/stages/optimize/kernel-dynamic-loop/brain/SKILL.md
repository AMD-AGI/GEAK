# Brain

Remain the controller: **Reasoning → Plan → Module → Report → Reasoning**.
Use the parent's task, current steering, selected mode and knowledge restrictions.
Modules may propose directions; the next call and stopping decision remain here.

Reconcile the actual task source and worker receipts with prior `RUN_DIR/HANDOFF.md`.
A rejected or pending handoff is not the worker's accepted source. Keep
`RUN_DIR/STATE.md` as a compact index of the accepted reference, inner incumbent,
useful candidate alternatives, evidence paths, open questions and running handles.
Native validity, measured effect, inner admission and parent acceptance are separate.
Keep useful small gains for later combination or the parent's check; do not lose their
source when an inner threshold rejects them. Native receipts and worker accounting own
results. A bookkeeping default is not a measured source reference. Reuse qualified
inputs and record the next inspection/report time.

## Decide and act

1. Read new and partial reports alongside running work and current steering. Rank useful
   questions by recoverable cost in the weighted native workload, observed bottlenecks,
   uncertainty and cost through verification and delivery. Use per-case evidence rather
   than a best-case speedup alone. Use the workload's
   [experience guidance](../../../../brain/experience/README.md) within this task's scope;
   a missing historical match does not exclude an opportunity.
2. Choose a module and then its implementation under the
   [call contract](../stages/CONTRACT.md). Write a bounded `PLAN.md` stating what evidence
   would change the next decision. Reuse observations or request a discriminating probe
   of the actual entry and settings. A proxy answers its own question, not the full task.
   Do not turn a missing measurement into evidence of no optimization space.
3. Dispatch ready independent work on separate source copies within assigned resources.
   Act when a report arrives without waiting for unrelated calls. Inspect real progress
   and measurements; hold only affected work when a call fails. A frozen-task or binding
   defect returns to the parent for requalification, not an edit to the test.
4. Read the native verdict, reconcile source identities and update the index. Advance the
   inner incumbent only under the shared contract. When progress is flat, identify what
   the evidence ruled out: change mechanism or scope, revisit Profile / Research, or
   Integrate complementary gains. Different case regimes may justify a dispatch candidate
   when the parent permits it. A merge or dispatch change is new source for Verify.
   Reorder work and budgets; repeat a probe because it resolves uncertainty, not to fill time.

## Starting route and continuation

When no stronger plan exists, establish or reuse Setup / Benchmark evidence, Profile the
current cost, Optimize a hypothesis and Verify it. Return to Reasoning after each call.
Research, Integrate and Learn are available when they answer the current question.
Use [Task](../stages/task/README.md) when full-test cost limits exploration, then Profile
its scoped probes and reserve full Verify for promising candidates. A direction budget
is a ceiling, not a catalogue to fill; reports determine the next useful direction.
Every module, including Profile, may repeat; a pass through the catalogue or one accepted
candidate does not finish the search.

Use observed source-specific test costs under the shared budget contract; timeout
ceilings are not expected durations. Keep room to Verify and Deliver a promising result,
and revise the plan when measured cost changes. Snapshot useful sources and native
receipts before long calls or handoff, so resumption does not depend on a mutable tree
or a final timer. Resuming a module does not restart the clock.

Checkpoint after meaningful reports and send concise Plan / Finish updates to the parent
at its cadence. Retain durable handles/logs for calls that outlive an interactive tool
session. On runtime or storage failure, hold affected work, preserve completed evidence
and return the required recovery to the parent; do not edit the frozen test.
Stop on task completion, exhausted assigned limits, a parent stop or an established
resource/prerequisite limit; a rejected candidate alone is not such a limit.
Use [Deliver](../stages/deliver/README.md) before returning. The parent owns final KEEP,
cold checks and serving acceptance; this loop reports kernel-level evidence only.
