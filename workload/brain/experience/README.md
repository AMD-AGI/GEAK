# Experience

Brain owns experience retrieval and its effect on planning. Start with [INDEX.md](INDEX.md),
or the external index selected in `BRIEF.md`; record its version and allowed origins there.
The index exposes origins and search tags, not scores or recommendations. Filter origins
before opening cases/routes and their linked raw evidence. Keep information exclusions
separate from permitted changes.

For a transfer test, give a fresh planner an origin-filtered index or packet before
it reads history. The target contributes its original inputs and this run's observations.
Filter derived summaries, mixed collections and worker inputs too.
Check worked examples and template defaults in module handoffs, including suggested
matches and tolerances. Use the current computation and its native validation owner
to justify the contract. Record the sources and freeze the first plan before revealing
held-out outcomes to the evaluator.

For a moving performance target, refresh the permitted source and select a point with the
same external workload, resources and metric definitions. Pin its date and reuse it until
the target or operating conditions change. Differences in engine, parallel layout or
scheduling are hypotheses for the observed gap.

When improving a supplied image, pin it as the candidate's base. Trace a later
release to the changed call sites, activation conditions and dependencies. Port a
measurable change onto the supplied stack and compare it there. Keep the published
release score as a reference for the remaining gap.

Retrieve by the cause of cost. Match the hardware, layout and operator semantics.
Estimate coverage in the requests and phases that drive each objective. A common
batch shape can be rare among slow requests. Where outcomes differ, use a losing
case to identify a transfer condition. An unavailable
implementation can still suggest a compatible probe or a scoped port.

Combine current Profile hotspots with relevant mechanisms, retaining hotspots without a
historical match. Rank plausible serving impact and remaining headroom against the full
incremental delivery cost and usable parallel resources. A high-impact unknown can justify
a bounded discriminator. History retrieval is not a gate for ready independent work.

In `PLAN.md`, connect the observation and case to the next module call. For a bundle,
choose the smallest comparison the runtime supports and name the dependencies that
change with it. An intermediate can distinguish which phase merits development.
State the outcome that changes priority. If a promising route must wait, identify
which report or observation will reopen it. Pass the relevant evidence by reference.

On a new Report, re-rank the work that still executes, including ordinary fallback
paths. Revisit history when the bottleneck, applicability or uncertainty changes.
Historical gains/costs are priors, not current measurements or stopping criteria.
Source changes, actual activation, bundled observations and local toggle pairs stay distinct.
Retrospective case summaries are not verified predecision reasoning. Preserve exact metric
and protocol identities; native validation remains with its owner.

Keep meaningful new observations with their campaign. Add a source-linked case or evidence
version when reusable: **conditions → mechanism → observed result/cost → limits → next
discriminator**. Preserve failures, negative results and unknowns. [Raw](raw/README.md)
collections remain unchanged; revise derived notes instead. Compare planners from
the same starting artifact, permitted knowledge and budget. Track time to a verified
serving gain alongside the final result.
