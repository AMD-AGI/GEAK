GEAK · 可切换 code-agent 后端

让 GEAK 的优化流程能换用 qcoder(Qwen Code) 或 Claude Code —— 一个开关切换,核心流程一字未改。

分支 test/code-agent-swap · 未提交 · 待 node 环境验证

为什么不能直接换 qcoder

GEAK 的流程写在 kernel_workflow.js / e2e_workflow.js 里,满篇是 agent() parallel() workflow() —— 这些不是普通 JS,是 Claude Code 私有的编排功能。 qcoder 打开这个文件一行都跑不了。

再加上:qcoder 的并行是"模型临时决定的"、且子任务不能嵌套,而 GEAK 的 e2e 恰恰要递归套娃。 所以只能在旁边搭一层适配,而不是去改 GEAK。

适配 qcoder:每个坑 → 对策 → 为什么

#qcoder 的坑我做了什么文件为什么
1 不认识 GEAK 的流程语言(agent/parallel/workflow 是 Claude Code 私有) 自己写一个最小流程引擎,让普通 Node 能跑那个 .js run_workflow.mjs 硬门槛:文件先跑得起来,后面才谈得上
2 并行靠不住 + 子任务不能嵌套 把并行、套娃放进运行时用进程级实现;qcoder 只当一次性单活 run_workflow.mjs 方案关键:不依赖 qcoder 的并行 → 你担心的问题直接绕开
3 不保证返回规整 JSON(Claude 有强制机制,它没有) 追加"只输出 json 块"要求 + 自己抽取/校验/重试,失败返回 null schema.mjs 最大风险点:得真跑才知道它听不听话
4 命令行调用方式不同(qwen -p --yolo、OpenAI 兼容 env) 封装"怎么正确启动 qcoder 进程" backends/qwen.mjs 唯一纯为 qcoder 写的文件;细节关在一处
5 入口得能选用 qcoder 加开关 GEAK_AGENT_BACKEND=qwen run_e2e.py 一个环境变量切换,默认行为完全不变

改造前 vs 改造后

改造前

  • 只能用 Claude Code,和框架焊死
  • 换 agent:做不到
  • 并行 / 套娃:由 Claude Code 负责
  • 想用 qcoder:流程文件根本跑不起来

改造后

  • claude / qcoder 可切换
  • 换 agent:改一个环境变量
  • 并行 / 套娃:由运行时负责,不依赖 agent
  • 默认行为 不变(不设开关 = 老路)

用法

# 用 qcoder 跑 e2e(不设这个变量 = 原生 Claude,行为不变) export GEAK_AGENT_BACKEND=qwen npm i -g @qwen-code/qwen-code # 需 Node ≥ 18 + 可达 Qwen 端点 python interface/run_e2e.py handoff.json result.json # 单内核直接用运行时 node interface/runtime/run_workflow.mjs kernel_workflow/kernel_workflow.js --args '{...}' # 逻辑自测(无需 GPU/网络) node interface/runtime/selftest.mjs

GEAK · switchable code-agent backend  ·  一句话:没有改 GEAK 去迁就 qcoder,而是补齐 qcoder 缺的能力,再用一个开关把它接进来。
