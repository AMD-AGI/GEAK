# Hardware peaks — generated planning references

These dense, per-precision reference values come from GEAK's shared
[`sku.json`](../../../../perf_knowledge/hardware/data/sku.json).
Edit the JSON, then run `python3 kernel_workflow/scripts/kernel_tools/extract_sku.py --sync-docs`.
Native TraceLens models and calibration remain independent.

- `resolve_peaks` selects the observed product through the shared run context.
- `load_peaks` may read labelled architecture defaults for offline reference only;
  an architecture default never establishes physical product identity.
- Memory uses the pin rate when recorded; historical or derived values retain
  their source basis. Missing rates/cache capacity stay unknown.
- Matrix and vector rates must not be interchanged. BF16 follows FP16 where the
  catalog explicitly records that equivalence; sparse rates are excluded.
- Local references cannot authorize candidate acceptance or optimization closure.
