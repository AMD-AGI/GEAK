# Native TL row, operation identity, and call stacks

Use this contract when explaining a device kernel, reviewing model coverage, or
preparing a TL issue. Start from `unified_perf_summary.csv` generated by the
selected upstream main commit with `--include_call_stack`. Keep the original CSV
unchanged and pass the complete selected row when practical.

## Capture and reporting are separate steps

For a new PyTorch trace, enable CPU and CUDA activities, `record_shapes=True`, and
`with_stack=True` after setup, compilation, and autotuning. Capture the actual
timed operator, not a correctness wrapper that gathers or concatenates results.
Attention models may also require framework inference annotations; shapes and
stacks alone do not replace sequence statistics. For graph replay, follow the
selected TL version's capture/replay merge workflow to recover host metadata.

Generate the native report with:

```bash
python3 -m TraceLens.Reporting.generate_perf_report_pytorch \
  --profile_json_path case_trace.json \
  --gpu_arch_json_path frozen_arch.json \
  --output_csvs_dir results/tl-only/native_csv \
  --enable_pseudo_ops \
  --include_call_stack
```

Check current `--help` before use. Existing traces without Python frames cannot
gain those frames from `--include_call_stack`; preserve the available CPU-op
chain, mark missing detail, and recapture when attribution depends on it.

## Minimum row context

| Field | Interpretation |
| --- | --- |
| `name` | The TraceLens operation/pseudo-operation used to resolve the model. It is not the device kernel name. |
| `perf_params` | TL's parsed model parameters, including dimensions, dtypes, and available inference statistics. Preserve them verbatim. |
| `kernel_details_summary` | Structured entries for the device kernels belonging to the operation; each entry's `name` is a device symbol. Keep all entries and their statistics. |
| Call-stack data | Every subkernel's launch chain, either inside its detail entry or encoded in `call_stack_full`, depending on TL version. |

Also retain native model/roofline fields, `has_perf_model`, `Compute Spec`, input
metadata, operation count, timing statistics, and row identity (`ex_UID`, process,
thread, source CSV hash, and CSV row ordinal when present). The minimum fields
identify a model; they alone do not establish a measured roofline or valid scope.

In main commit `90f2f6f58210d1828c5eca6949b1dce7d2525fa7` (checked 2026-11-04),
`--include_call_stack` builds `call_stack_full`, then removes internal `call_stack`
and `gpu_op_uid` fields from `kernel_details_summary`. A single kernel has a flat
chain. Multiple kernels have a common prefix followed by nested per-kernel tails,
whose final element is the device name. Some older reports retain per-entry
`call_stack` instead. Inspect the actual schema; do not require both layouts.
This commit documents the checked format, not a pin for future analyses.

Match full stack branches to exact device names. Preserve multiple candidates
when names repeat; do not assign branches by a guessed positional order. Keep
full data even if a displayed stack tail or `trunc_kernel_details` is shortened.
Read CSV with a CSV parser and nested cells with JSON or a restricted literal
parser, never `eval` or comma splitting. Current reports can serialize NumPy
scalars as `np.float64(10.0)` or `np.int64(10)` inside these cells. The bundled
helper unwraps only allowlisted scalar constructors with literal numeric payloads
through an AST transform, without executing calls; it retains the original cell.

## Package a row for an agent

```bash
python3 scripts/extract_tl_row.py \
  --csv results/tl-only/native_csv/unified_perf_summary.csv \
  --row-index 0 --tl-commit "$TL_COMMIT" \
  --out results/tl-only/selected_row.json
```

`--row-index` is zero-based among data records, not text lines (cells may contain
newlines). The helper preserves the native row, all siblings, and model fields;
its per-kernel view only organizes identity and stacks. It does not import TL,
select a model, change bytes, or compute a roofline. Missing and ambiguous stacks
remain explicit. If the CSV schema cannot be parsed, retain the row and inspect
the native file instead of inventing a mapping.

For each kernel under review, provide the operation `name`, `perf_params`, exact
device name/detail, and its stack or all candidate stacks, together with the
full parent row. Do not assign the parent's whole FLOPs/bytes to each subkernel,
divide by one subkernel's time, or count the same operation once per child.

For example, this supplied MLA decode context identifies two different names:

```text
operation name: pseudo_mla_decode_fwd
device name: aiter::mla_a16w16_qh16_m16x4_n16x1_coex0_mask1_ps
perf_params: B=1, N_Q=32, H_Q=16, d_h_qk=576, d_h_v=576, g_sk=49598, BF16
launch-chain tail:
  vllm::unified_mla_attention_with_output
  -> rocm_aiter_mla_sparse.py forward_mqa / _forward_mla
  -> vllm/_aiter_ops.py mla_decode_fwd
  -> vllm::rocm_aiter_mla_decode_fwd
  -> aiter/mla.py mla_decode_fwd
  -> pseudo_mla_decode_fwd
  -> aiter::mla_decode_stage1_asm_fwd
  -> [device name above]
```

The operation selects the TL model. The stack establishes the launch path and
helps inspect whether the model fits this implementation. Neither the word MLA
in a symbol nor a familiar dimension justifies silently changing `d_h_v`, bytes,
precision, or model selection. Other children, such as a reduction, remain part
of the same operation row unless TL explicitly models separate operations.

## Before claiming a TL defect or missing coverage

For standalone UTs that lack native CPU operator identity, follow
[ut-context.md](ut-context.md) first. Source-reviewed identity and parameters can
enable an existing native model. Preserve the raw trace and label this input
enrichment in every exported row; native `perf_params` are still TL's output.

1. Resolve fresh upstream main and record the exact commit, import path, local
   changes, report command, and arch file/hash. Reproduce on that commit, not an
   old campaign wrapper that calls TL static functions and adds its own formulas.
2. Attach the native row and stack context above. Inspect `name` in TL's ordinary
   and pseudo-op registries and inspect `perf_params`, annotation completeness,
   model status, and peak selection. A task called `indexer_preamble` may appear as
   different native operations; absence of the task label is not proof of no model.
3. State the actual and expected behavior with a minimal input trace/model event.
   Distinguish mapping/annotation errors, model coverage, byte-model assumptions,
   absent peaks, and report limitations. A populated report does not prove the
   modeled bytes represent HBM transactions or account for shared storage/reuse.
4. Preserve all affected subkernels and the timing/cache contract. For sparse
   shared-latent issues, include alias/layout facts and selection metadata; do not
   substitute unique bytes silently. A call stack helps attribution, not cache
   traffic measurement. Counter evidence is optional and separate from TL-only.

Prepare evidence locally; this workflow does not itself post an issue or send a
message to maintainers.
