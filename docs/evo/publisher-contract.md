# Retained publisher and cleaned producer contract

The cleaned engineer always records `native_trial_history` in its parent
snapshot. The retained finite publisher originally required the older exact
snapshot fields and rebuilt only selected, faithful, unfinished and terminal
roles. It therefore rejected the first cleaned snapshot and could not validate
retained trial sources. Its generated tool instructions also differed from the
cleaned producer, which changed the entry hash and three dependent references.

`publisher-contract.patch` applies after `owner-dispatch.patch` and
`native-search-phase.patch`. `publisher-contract-base.json` pins both the composed
input bytes and resulting bytes for the wrapper, coordinator and publisher.
The packet builder must verify both hashes before publishing the source packet.

The wrapper reads a fixed nine-module closure from the same complete, immutable
source manifest as the ordinary cleaned producer. It executes the checked source
bytes in `_geak_evo_publisher_contract`, with empty package paths, and passes the
readers explicitly through `coordinator.main` to `Publisher`. Canonical retained
`geak_evo` imports remain in place. No cleaned host, model transport or native
launcher is loaded by this closure.

The producer and publisher share the existing trial-aware parent projection,
source/evidence corpus and parent material functions. `parent_snapshot` is the
pure projection extracted from `parent_prompt_context`; that producer still
archives the same candidate-bound evidence. `archive_files` moves from engineer
assignment into succession and remains imported at its original interface.
The publisher retains its exact schema, historical state, accounting, claim,
source, revision and evidence-envelope checks, then recomputes and compares the
complete parent snapshot, including the full trial projection. It accepts the
new field only when the owner supplies the explicit shared contract.

The historical view exposes two additional existing read APIs, `_bytes` and
`evidence_artifact`. The retained Store predates `_bound_evidence`, so the owner
also supplies that exact cleaned read method. The view invokes it on the same
retained Store; its existing `_object`, `_candidate` and `_binding` checks remain
authoritative. No second runtime store is opened and no all-artifact fallback is
used for a selective read.

`engineer.instructions.tool_addendum` is the existing deterministic instruction
recipe extracted without changing its output. Both sides use it after applying
their reservation clamp and operation bindings. The retained publisher still
independently validates copied context, descriptor scopes and all other native
file fields. Legacy callers without the contract keep their existing behavior.

CPU validation uses actual producer outputs and retained consumer code:

- `test_publisher_parent_contract.py` uses cleaned and retained Store instances
  over one temporary archive. It covers the seed, repeated retained trials,
  failed outcomes, feedback stages, engineer attribution, source filtering,
  exact source/evidence corpus and a tampered but validly archived projection.
- `test_publisher_operation_contract.py` compares all five generated JSON files
  byte for byte in native-only and diagnostic modes, using real temporary
  references and copied context. It checks the reservation clamp and rejects
  tampered prompt bytes and descriptor read scopes.
- `test_publisher_contract_loader.py` checks the fixed authenticated source
  closure, unchanged canonical imports, hash rejection and missing inventory.
  Only root-owned filesystem ancestry is replaced for the ordinary checkout.

These checks establish source and synthetic CPU compatibility at the reviewed
boundaries. They do not establish an installed engineer seal, native execution
and collection roundtrip, or any performance result.
