# CDNA4 / MI350X / MI355X (gfx950) — peak throughput tables

> **All numbers are theoretical (datasheet) peak.** Sustained is well below (MI300X-class kernels see
> ~45%; expect similar fractions on CDNA4 pending broad measurement, arXiv 2510.27583). Quote
> *achieved*, and every "% of peak" against these numbers carries `denominator_basis: datasheet` —
> it may rank, never gate or close ([../../profiling/roofline_on_mi.md](../../profiling/roofline_on_mi.md)).

## TL;DR
> **MI355X and MI350X do NOT share peaks.** Same gfx950 silicon (256 CU, 1024 matrix cores, identical
> per-CU per-clock rates) at different peak engine clocks — **2400 vs 2200 MHz** — so the datasheet
> peaks differ by 2400/2200: MI355X **FP16/BF16 2.5 PF, FP8 5.0 PF, FP6/FP4 10 PF, FP32 157.3 TF,
> FP64 78.6 TF**; MI350X **2.3 PF, 4.6 PF, 9.2 PF, 144.2 TF, 72.1 TF**. Both: HBM3E **288 GB /
> 8 TB/s**. **~2× FP16/FP8 vs CDNA3**; **TF32 removed**; FP64 **matrix** halved.

## Matrix / vector peaks (per OAM, vendor-reported, dense)
| Computation | MI355X | MI350X | vs FP32 | vs CDNA3 (MI300X / MI325X) |
|---|---|---|---|---|
| FP64 vector = matrix | 78.6 TFLOP/s | 72.1 TFLOP/s | 0.5× | vector ~same / matrix halved (163.4 → 78.6) |
| FP32 vector = matrix | 157.3 TFLOP/s | 144.2 TFLOP/s | 1× | ~same |
| FP16 / BF16 matrix | **2.5 PFLOP/s** | **2.3 PFLOP/s** | 16× | **~2×** (1307.4 → 2500 / 2300) |
| FP8 (OCP) matrix | **5.0 PFLOP/s** | **4.6 PFLOP/s** | 32× | **~2×** (2614.9 → 5000 / 4600) |
| FP6 matrix | **10 PFLOP/s** | **9.2 PFLOP/s** | 64× | new |
| FP4 matrix | **10 PFLOP/s** | **9.2 PFLOP/s** | 64× | new |
| MXFP8/6/4 | matches element rate | matches element rate | — | new |
| INT8 | 5.0 POPS | 4.6 POPS | 32× | ~2× |
| TF32 | **removed** | **removed** | — | gone |

FP6 and FP4 share the FP4 rate. The two columns are the same per-CU rate at the two peak engine
clocks; on top of that, MI355X's 1400 W (liquid) envelope also *sustains* clock better than MI350X's
1000 W (air) — see [clocks_power.md](clocks_power.md). Never quote one SKU's peak for the other: use the
detected product (`scripts/gpu_identity.py` field `sku` → `mi355x` / `mi350x`).

## Memory & cache peaks
| Resource | Value |
|---|---|
| HBM3E capacity | **288 GB** (8 × 36 GB, 12-Hi) |
| HBM3E bandwidth | **8.0 TB/s** |
| Infinity Cache (MALL, memory-side) | 256 MiB — behind the fabric, NOT L2 |
| L2 | **4 MB per XCD** × 8 XCDs = 32 MB aggregate (an XCD's CUs see only their own slice) |
| LDS | **160 KiB/CU**, **64 banks**, **256 B/clk** |
| L1 vector | 32 KiB/CU, 128 B line |
| Infinity Fabric (per card) | 1075 GB/s bidirectional aggregate (4th gen) |

FP16 roofline ridge ≈ 2.5 PF / 8 TB/s ≈ **312 FLOP/byte** on MI355X, 2.3 / 8 ≈ **288** on MI350X (vs
~247 on MI300X, ~218 on MI325X) → relatively more kernels are bandwidth-bound; byte-cutting matters
even more. The ridge is per dtype (MI355X fp4: 1250) and is computed, never stored.

## Peak formula cross-check
`peak = 2·M·N·K · 1024 cores · (clock / cycles)`. With 256 CU × 4 = 1024 cores and the **2× per-CU**
matrix rate, the FP16/FP8/FP6/FP4 peaks above follow from the CDNA4 cycle counts in
[matrix_core_blockscale.md](matrix_core_blockscale.md) (FP6/FP4 use the lower cycle count when neither
operand is FP8 → 2× the FP8 rate → 10 PF). Equivalently, FP16 dense = 4096 FLOP/clk/CU × 256 CU ×
clock: × 2.4 GHz = 2.52 PF (MI355X), × 2.2 GHz = 2.31 PF (MI350X).

## Sustained reality
No large public sustained-of-peak dataset for CDNA4 yet (as of 2026-06). On MI300X the sustained
fraction is **~45%** across FP8/BF16/FP16 (arXiv 2510.27583); treat CDNA4 similarly until measured.
Record any measured number as `value @ MI355X gfx950, ROCm <ver>, <lib>@<ver>, <date>` — a measured
ceiling is a `denominator_basis: empirical@<tool>-<version>` and belongs in `sku.json`
`measured_ceilings`. Counter-based achieved bytes on gfx950 need care: `FETCH_SIZE` / `TCC_BUBBLE`
under-count read bytes there ([../../profiling/roofline_on_mi.md](../../profiling/roofline_on_mi.md)).

## MLPerf Inference v6.0 (the achieved-throughput anchor)
The strongest public end-to-end CDNA4 numbers. **MI355X 1-node Llama2-70B**: offline **103,480** / server
**100,282** / interactive **73,608** tok/s; **gpt-oss-120b** server up to **115%** of OEM B200. Versus
**NVIDIA B300**: **92%** offline, **93%** server, **104% interactive** — AMD **wins interactive**. Llama2-70B
improved **4.4–4.8× over v5.1**, driven by **FP4**. Stack: **vLLM + AITER + Quark + GEAK + QuickReduce**.
Note: NVIDIA **GB300 still leads raw reasoning per-GPU** (DeepSeek-R1). Use these as the achieved-throughput
reference against the theoretical peaks above.
