## Retrieval metadata backfill (2026-08-13) — P0–P3, the index stops idling
- **P0 — two structural bugs.** `kb_resolve.matches()` treated an *unset* `kernel_class` as EXCLUDE while `platforms`/`skus` treated unset as WILDCARD; any `--kernel-class`/`--operator` query therefore could never return a cross-cutting doc, hiding all 87 files (11,476 lines) of `hardware/ optimization/ profiling/ quantization/ workflows/ landscape/` no matter how well labelled. Unset is now a wildcard, and `sort_key()` gained a defaulted 3rd param so an exact class match still outranks a wildcard at equal cost (cost stays the primary key). Added `--operator`, which translates a taxonomy operator id to a `kernel_class` through `_kb_vocab.kernel_class_for_operator()` — the one bridge between the two vocabularies, deliberately kept out of the role prompts. `_gen_index._line()` relpath'd against `VIEWS` while writing into `VIEWS/<subdir>/`, one level deeper, so **every** generated link was short one `../`: 1,972 broken links, now 0.
- **P1 — rule-derived labels** (`index/_label_kb.py`, 382 rows). `operators/` is a regular grid (54 × {overview,tuning,numerics,fusion} + `backends/<taxonomy-id>.md`), so a ~30-line selector table covers ~380 files with no guessing: library backend → L2 `[backend.swap]`, DSL/hand-written backend → L3, `tuning.md` → L1 `[config.per-shape-tune]`, `numerics.md` → `risk: numerics-affecting`, `overview.md`/`fusion.md` → cost deliberately unset so navigation docs sort behind actionable cards. Precision/recall is picked per field by how the resolver *punishes* a mistake: a wrong `cost` both mis-sorts and gets pruned under `--max-cost` (precision-first, rules only), a missing `bound_type` is simply unreachable (recall-first, cap 2). Naive keyword matching for `levers` was measured and rejected — 4.49 tags/file of noise.
- **P2 — 111 hand labels** over `optimization/`(11) `quantization/`(9) `hardware/`(27) `profiling/`(6) `workflows/`(8) `case_studies/`(9) `backends/`(35). `hardware/` gets `bound_type` but no `cost` on purpose: a hardware doc describes a ceiling, it is not a lever. This is the layer that makes `--bound` work.
- **P3 — 387 operator rows** (`index/_p3_operator_bounds.py`), evidence + physics: 8 unambiguous bottleneck regexes over each operator's `overview.md`, unioned with a per-`kernel_class` prior whose head keeps a definitional slot (an all-reduce card that happens to say "bandwidth-bound" in prose must still be reachable from `--bound sync`). Every row carries its citation and lands as `src: llm`, ranking below the hand labels.
- **Provenance, not a second index.** `index/kb_labels.yaml` (880 rows) is a checked-in *proposal ledger* — `src: rule|llm|human` + `evidence` per row, precedence `frontmatter > human > llm > rule`, apply is ADD-only and never overwrites an existing key. File frontmatter remains the only thing `_gen_index.py` reads. Re-running the whole chain is a no-op.
- **Result:** `levers` 2 → 270 · `bound_type` 2 → 452 · `cost` 0 → 330 (316 left unset by design) · empty `views/by_lever/*.md` 19/21 → 0/21 · broken links 1,972 → 0 · validator warnings 922 → 411 (0 errors throughout). Six of the eight `bound_type`s used to return **zero** cards; all eight now return ≥5 (hbm_bw 346, mfma_compute 162, launch_overhead 176, sync 46, l2_locality 27, occupancy 27, lds_bank 18, host_bound 7). `test_kb_resolve.py` 12 → 22 tests, including `TestCommittedManifestCoverage` which asserts that floor against the *committed* manifest — the G1 merge gate, so "is the KB labelled well enough to wire up?" is a CI invariant rather than a feeling.

## G1 wired (2026-08-13) — the KB stops being reference-only
- **Read path.** `kernel_lane.js` gained `use_kb_resolve` (**default ON** — G1 asks for a dependency, not an opt-in) and a `kbResolveBlock(role)` shaped exactly like `expertSkillsBlock`, so `use_kb_resolve=false` reproduces the pre-feature prompts byte for byte. tech_lead `analyze` gets the tool but no routing keys (it runs before the Profile phase, and inventing a `--bound`/`--gfx` prunes the right cards); `plan_round` and the `deep_explore` engineer get `KB_GFX` + `KB_BOUND` derived from `PROFILE_SUMMARY`. The specialist engineers get nothing: they already receive the TechLead's per-direction `kk_refs`, and self-querying would widen a deliberately narrow mandate.
- **Both routing keys are derived defensively in JS, not trusted from the agent.** `PROFILE_SCHEMA.bound_type` and `device` are free strings with no enum, so an agent legitimately answers "memory bandwidth bound" or omits the gfx target. Both are validated against the vocabulary and fall back to `''` — never to a guessed `gfx942`. An unrecognized `--bound`/`--gfx` matches ZERO cards, which is strictly worse than omitting the flag, which widens to a superset. The role files are told to omit any empty flag.
- **Write path.** A validated lane win now distils one card into `kernel_workflow/knowledge/learned/` through the existing `roles/update_experience.md`. Two gates the bake-off caller does not have, because `LAYER_RANK` puts `learned` ahead of `reference` at equal cost and lanes are frequent — one noise card would permanently shadow the real documentation: **≥1.05×** (not >1.0×) and `validation_status` must say pass. The card must carry `bound_type`, which is what makes it reachable by the very query that found the problem; the schema in `learned/README.md` was missing that field while its own text told agents to query with `--bound`. `update_experience.md` now documents both callers (the lane has no `KB_ARTIFACTS_DIR`, and that is normal), derives `kernel_class` via `_kb_vocab.kernel_class_for_operator()` instead of the non-existent `index/signature_map.yaml`, and spells out the lane's cost rule (L3 default, L1 config-only, L0 env-only). Re-indexing is opt-in (`kb_reindex_on_win`, default off — `_gen_index.py` rebuilds `views/` by rmtree-then-write, which is racy against a concurrent lane).
- **Three regression guards, all registered in `ci-l0-checks.yml`** (its pytest/node lists are explicit — an unregistered test does not exist): `test_kb_resolve_off_identical.js` (OFF injects nothing · ON is role-scoped with a fixed key shape · the derivation rejects free-string values · **the JS `BOUND_TYPES` literal equals `_kb_vocab.BOUND_TYPES`**, or every `--bound` query silently goes empty), `test_write_on_win_gates.js` (thresholds, payload completeness, non-fatality), and the existing 22-test `test_kb_resolve.py`.
