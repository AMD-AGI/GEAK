# AMD RDNA4 — SKU planning peaks (gfx120* / gfx1201)

**Planning models, not guaranteed sustained rates.** RDNA4 client parts (discrete
RX 9070 / workstation R9700). **WMMA path with FP8 matrix on gfx12** — no `mfma_scaled`,
no OCP FP4 (INT4 matrix only). Optimize via the RDNA WMMA path — see
`rdna-fork.md` and your DSL's WMMA reference. ISA PDF:
[RDNA4 shader ISA](https://www.amd.com/content/dam/amd/en/documents/radeon-tech-docs/instruction-set-architectures/rdna4-instruction-set-architecture.pdf).

```text
saturation = grid_tiles / CUs
L2_MB      = die L2 (ROCm); not Infinity Cache
ridge      = FP16 matrix peak / peak HBM BW   (ops/byte)
```

**This `saturation` is the coarse fill check, not the quantization tail.** It answers *does the
grid cover the device at all*, and it is **not** `tail_efficiency` — it says nothing about how
much of the *last* wave is wasted. That quantity is `grid_tiles / (waves * CUs)`; mechanism in
`roofline-models.md ## Saturation / wave quantization`, and the rule that it is one-sided — it
can veto a geometry but **cannot rank two configurations** — in
`planning-constants.md ## Tail efficiency is one-sided too`.

**gfx1201 (RDNA4) is not gfx1250 (CDNA5 / MI450)** — RDNA4 is occupancy-first WMMA
with no TDM / named-barrier warpgroups; do not transfer gfx1250 data-center assumptions
here (`rdna-fork.md`, `planning-constants.md ## gfx1201`).

## Instruction set (gfx120* / RDNA4)

| Mechanism | RDNA4 (gfx1200 / gfx1201) | Notes |
| --- | --- | --- |
| Wave32 WMMA 16×16×16 | ✓ f16, bf16, i8, iu4 | **v8-operand** ABI (vs RDNA3 v16) |
| **FP8/BF8 matrix (WMMA)** | ✓ `V_WMMA_F32_16X16X16_FP8_*` | RDNA4-only; **no** native FP8 on gfx11 |
| Block scale / `mfma_scaled` / OCP FP4 | **✗** | dequant + WMMA, or IU4 WMMA |
| SWMMAC 4:2 sparse | ISA ✓ | DSL path `unknown-needs-probe` |
| `GLOBAL_LOAD_TR_*` transpose load | ✓ | RDNA analog of CDNA `ds_read_tr` |
| Async→LDS / TDM | **✗ (ISA: none)** | TDM is gfx1250/CDNA5 — hand LDS ping-pong |
| Dynamic VGPR (`S_ALLOC_VGPR`) | **✗ (not RDNA4)** | rejected by ROCm 7.1 / LLVM 20 on gfx1200 **and** gfx1201 — a gfx1250/CDNA5 feature (`rdna-fork.md` §Dynamic VGPR) |
| MFMA (CDNA) | ✗ | RDNA, not CDNA |
| Matrix/VALU co-execution | **✗** | WMMA cannot co-issue with VALU (CDNA MFMA can) — no "hide VALU under the matrix op" lever here |

**Compile / runtime**: `HCC_AMDGPU_TARGET=gfx1201` (R9700) / `gfx1200` (RX9070*);
`ROCBLAS_USE_HIPBLASLT=1` for GEMM. Do not apply CDNA wave64 / combined-512-VGPR
occupancy formulas (`rdna-fork.md ## Occupancy note`).
