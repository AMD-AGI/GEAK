# RoPE and KV-cache write: native numerics facts

Covers the rotation of q / k (operator `rope`), the model-side steps between the qkv projection and the
attention call (packed split, v multiply, per-head q / k norm) and the write of the current token's K / V
into the paged cache (operator `kv_cache_quant`), for vLLM on ROCm: the rotary module's C kernel and
torch-native paths, the Triton cache write of the diff-KV backend, and a model-level fused
q/k-norm + RoPE + KV-insert HIP kernel. Not here: how the attention kernel reads the cache
(`attention_decode.md`), MLA and sparse-attention caches (`mla_and_sparse_attention.md`), SGLang
(`sglang_backends.md`).

**Versions.** Line numbers are valid at vLLM commit `f09d5e30c`, aiter tag `v0.1.26` (rows marked
`@285579b6` were read at that aiter commit) and, for SGLang, commit `22e1cb6d98`; in any other version
locate the code by symbol.

**Status.** `capture` = verified on a model capture (a captured decode step of a served model was reproduced
with this fact; "2 models" when two served models agree). `probe` = verified by a real-op probe (the installed
native op was run on synthetic inputs and compared with an emulation of this fact, usually bit for bit).
`source only` = read from source, never run against the native op: treat it as a suspect and confirm it with
the flip test in `parity_method.md` before relying on it.

**Model-package tags.** `<PKG_POSTNORM_MOE>` = the package, under `vllm/models/`, of the post-norm MoE model
with fused norm / routing kernels (the one containing `common/ops/fused_rmsnorm.py`); resolve a tag by listing
`vllm/models/` in the checkout.

## Which backend is running

The rotation is model code and does not depend on the attention backend; the cache write does.

| Path / provider | Selected when | Where to read it |
|---|---|---|
| RoPE: C kernel (`ops.rotary_embedding`, in place) | the rotary custom op is enabled and the aiter Triton rope is not selected | `compilation_config.custom_ops` after the config post-init: enabled iff (base mode `all` or `+rotary_embedding`) and no `-rotary_embedding`. The base mode is `none` when the model is compiled with Inductor and `all` otherwise (eager); the `fuse_rope_kvcache` pass config appends `+rotary_embedding` |
| RoPE: aiter Triton rope | custom op enabled and `VLLM_ROCM_USE_AITER=1` and `VLLM_ROCM_USE_AITER_TRITON_ROPE=1` (default off) | process environment. Numerics not read: no facts in this file |
| RoPE: torch-native, compiled by Inductor | custom op disabled and `compilation_config.mode` is not NONE with the `inductor` backend (the default compiled deployment) | same config, plus `torch._inductor.config.emulate_precision_casts` (`TORCHINDUCTOR_EMULATE_PRECISION_CASTS`, default off) |
| RoPE: torch-native, eager | custom op disabled and no compilation | same config |
| KV write inside the attention call (rotation and write are two kernels) | the backend's `forward_includes_kv_cache_update` is False (`ROCM_ATTN`, `ROCM_AITER_UNIFIED_ATTN`, `TRITON_ATTN_DIFFKV`) and neither fused path below is active | backend name in the server log line "Using ... backend"; the backend class attribute |

Numerics not read: no facts in this file |

| KV cache dtype | `fp8` / `fp8_e4m3` = the platform fp8 (e4m3fnuz on gfx942, OCP e4m3 on gfx950); `auto` / `bfloat16` = the model dtype | `cache_config.cache_dtype` (the `--kv-cache-dtype` option) |

Layer facts to read off the deployment before writing the kernel:

| Quantity | Where to read it |
|---|---|
| rotary dim, rotation style | `layer.rotary_emb.rotary_dim`, `.is_neox_style` (NeoX pairs (i, i + rot_dim/2), GPT-J pairs (2i, 2i+1)) |
| plain rope or not | the class of `rotary_emb`: plain when it keeps the base class forward (the scaling variants only change the table); a class that overrides the forward is not covered here |
| cos / sin table and its dtype | `layer.rotary_emb.cos_sin_cache` (its dtype after the first decode step) |
| v multiplier | the model's attention module (MiMo-V2.6-Flash: `attention_value_scale` in the config, held as `v_scale`); 1.0 when the model has none |

| cache strides, block size | `kv_cache.stride()` of the layer's cache tensor as the attention forward receives it; `cache_config.block_size` |
| `k_scale` / `v_scale` | the attention layer's `_k_scale` / `_v_scale` (fp32, one element each) |

## Packed split and v multiply

| id | Fact | Applies to | Status | Effect if wrong | Source |
|---|---|---|---|---|---|
| RKV-08 | A rank's packed qkv row is `[Q, K, V]` with each head contiguous (split sizes q, k, v; the v head dim can differ from the q / k head dim, e.g. 128 against 192). Exception in the `mimo_v2` model code: with a non-zero `kv_chunk_rows` (a rank owns several checkpoint chunks whose K and V rows share a scale block) the K / V part is `[K_1 V_1 pad, ..., K_g V_g pad]`. | RKV-09 | MiMo-V2.6-Flash multiplies v by a config constant (`attention_value_scale`, held as `v_scale`) after the rotation and before the attention call, when the constant is set: a bf16 tensor times a Python float. A kernel whose cut covers this step must apply it. | vLLM · `mimo_v2` model code · bf16 · gfx942, gfx950 | source only | dropping the multiply is about a 30 % error | `vllm/model_executor/models/mimo_v2.py:259`, `:372-374`, `:402` |
| RKV-10 | A bf16 tensor times a Python float is bf16(fp32(v) · fp32(c)): the scalar is rounded to fp32, one fp32 multiply, one rounding to bf16. ## Fused q/k-norm + RoPE + KV-insert kernel

One HIP launch called by the attention module of a post-norm MoE model with fused norm kernels (package
`<PKG_POSTNORM_MOE>`): weightless per-head q / k RMSNorm, GPT-J rotation or none, K / V insert into the paged
cache. The facts are keyed on the module's fused-insert flag, not on the model: any attention module that calls
this op gets these numerics. No served model was captured, so every row is `source only`; rows RKV-33 to
RKV-35 were additionally run against the real op on gfx942 with synthetic data, as each row says.
