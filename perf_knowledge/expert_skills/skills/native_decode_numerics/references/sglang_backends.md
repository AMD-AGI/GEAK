# SGLang ROCm backends: native numerics facts

Decode-regime facts for SGLang's ROCm (HIP) backends: the Triton attention decode and its KV-cache write, the RoPE
kernel, the sparse-MLA (`dsa`) and block-sparse attention backends, the aiter MoE router and experts, fp8
block-scale and bf16 linears, RMSNorm and the TP all-reduce. The vLLM facts for the same operator families are in
the sibling references (`attention_decode.md`, `rope_and_kv_write.md`, `mla_and_sparse_attention.md`,
`moe_and_routing.md`, `linear_and_gemv.md`, `norm_and_quant.md`, `tp_allreduce.md`). Where SGLang calls the very
same aiter kernel, a row says so and states only what SGLang does around the call.

**Read this first: almost every SGLang fact is read from source only.** Of the 560 facts behind this skill's
references 435 are source-read; of the 109 SGLang facts, 108 are. No reference built from these rows has been
compared with a captured SGLang decode step. The only row with run evidence is `SGL-17`, a real-op probe of the RoPE
kernel.
Kernel names quoted from "a profiler trace of a served SGLang decode step" show which kernel ran, not what it
computes. Treat every row as a suspect and confirm it with the flip test in `parity_method.md` before a candidate
kernel depends on it.

**Versions.** Line numbers are valid at vLLM commit `f09d5e30c`, aiter tag `v0.1.26` (rows marked
`@285579b6` were read at that aiter commit) and, for SGLang, commit `22e1cb6d98`; in any other version
locate the code by symbol. SGLang paths are repository paths (`python/...`); every aiter pointer in this file was
read at aiter commit `285579b6`.

**Status.** `capture` = verified on a model capture (a captured decode step of a served model was reproduced
with this fact; "2 models" when two served models agree). `probe` = verified by a real-op probe (the installed
native op was run on synthetic inputs and compared with an emulation of this fact, usually bit for bit).
`source only` = read from source, never run against the native op: treat it as a suspect and confirm it with
the flip test in `parity_method.md` before relying on it.

**Path globs.** A `*` in a path stands for one path component that carries a model name; the rest of the path is
unique in the checkout. Flags whose names carry a model name are given by their suffix.

## Not covered by any check

- No SGLang decode step has been compared with a reference built from these rows. The only run evidence is the RoPE
  probe (`SGL-17`) and kernel names from a profiler trace of one served deployment (MiMo-V2.6-Flash, TP 4, gfx942).
- gfx950 and gfx1250 paths: preshuffled fp8 linears, the small-M MoE and GEMM kernels, the fp32-P attention branch,
  hardware bf16 rounding. Only gfx942 was read in depth.
- Attention: the lean decode kernel, the one-query-head-per-KV-head kernel, MLA through the Triton backend, paged
  (page size > 1), `hnd` and `vectorized_5d` cache layouts, a unified pool whose reads are translated, non-unit K / V
  scales, a logit cap, decode context parallelism, speculative verify batches (more than one query token per request),
  a batch-dependent split count (width > 1 without static splits), deterministic inference.
- KV-cache labels other than fp8 e4m3 / e5m2 and bf16 (block-scaled or fp4 caches).
- RoPE: the native and compiled forwards, rotary classes that override forward, a q / k norm ahead of the RoPE.
- Sparse-MLA (`dsa`) backend: an fp8 latent cache, the aiter index-key writer's rounding, decode context parallelism,
  the non-fused top-k path's table translation.
- Block-sparse backend: page sizes of 16 and more, score types other than the block maximum, the fp8 index cache, the
  context-parallel indexer.
- MoE: routers other than aiter's register-resident kernel (grouped kernels with a group filter, SGLang's Triton and
  radix-4 routers, aiter's opt-in FlyDSL top-k), expert parallelism, fused shared experts, expert biases, activations
  other than SiLU, native MXFP4 experts (no load-time dequant), the 1-stage kernel above 32 tokens, tuned-config rows.
- Linears: SGLang's own Triton fp8 quant and GEMM (maximum, eps and division forms unknown), pre-quantised inputs from
  a fused producer, the skinny GEMV kernel's partial-sum format, tuned bf16 GEMM rows, act-and-mul epilogues.
- RMSNorm: aiter's generic kernel (fp32 input or hidden > 8192), the padded Triton variant, unit-offset norm classes, a
  norm fused with an fp8 quant or with the all-reduce.
- All-reduce: SGLang's own custom all-reduce (including the deterministic 1-stage kernel), the JIT v2, QuickReduce,
  PCIe-IPC, MSCCL++, RCCL beyond two ranks, partials that are not bf16.
