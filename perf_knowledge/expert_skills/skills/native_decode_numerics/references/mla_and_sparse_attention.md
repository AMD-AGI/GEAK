# MLA and sparse attention: native numerics facts

Operators: MLA decode over the latent KV cache (`mla_attention`), sparse MLA over an index list, the token-granular
and the compressed indexer with their top-k, the KV compressor, and block-sparse attention with a block indexer
(`sparse_attention_nsa`). Backends: vLLM `TRITON_MLA`, `ROCM_AITER_MLA`, `ROCM_AITER_MLA_SPARSE`, the AITER sparse
indexer, and three per-model packages (tags below). Not here: dense paged attention (`attention_decode.md`), RoPE
and KV write of non-MLA layers (`rope_and_kv_write.md`), SGLang (`sglang_backends.md`).

**Versions.** Line numbers are valid at vLLM commit `f09d5e30c`, aiter tag `v0.1.26` (rows marked
`@285579b6` were read at that aiter commit) and, for SGLang, commit `22e1cb6d98`; in any other version
locate the code by symbol.

**Status.** `capture` = verified on a model capture (a captured decode step of a served model was reproduced
with this fact; "2 models" when two served models agree). `probe` = verified by a real-op probe (the installed
native op was run on synthetic inputs and compared with an emulation of this fact, usually bit for bit).
`source only` = read from source, never run against the native op: treat it as a suspect and confirm it with
the flip test in `parity_method.md` before relying on it.

**Model-package tags.** Per-model packages under `vllm/models/` are written as tags; resolve a tag by listing
`vllm/models/` in the checkout.
- `<PKG_LATENT_SPARSE>`: the package of the sparse-latent-attention generation these rows were read in. Of the two
  packages that contain `sparse_mla.py` and `compressor.py`, it is the one that also contains
  `common/ops/fused_indexer_q.py`. The other one (it has `amd/ops/sparse_indexer.py`) is the `DeepSeek-V4.1` package:
  same family, its own code. For `DeepSeek-V4.1`, check that the same symbol exists in its own package before
  relying on a row; until then the row is `source only` for it.
- `<PKG_SMLA_PREV>`: the package of the previous sparse-MLA generation (contains `common/kernels.py`).
- `<PKG_BLOCK_SPARSE>`: the package of the block-sparse attention model (contains `common/ops/sparse_attn.py`).

**Symbols.** L = `kv_lora_rank`; N = query heads on the rank; P = no-RoPE query dims; V = value dims; B = decode rows;
CU = compute units of the serving device (304 on MI300X); "tolerance" = the stage tolerance derived as in
`parity_method.md`.

Deployment facts to record before using the tables below, and where each is read:

- Device arch: `rocminfo` or `torch.cuda.get_device_properties(0).gcnArchName`. It fixes the platform fp8 type
  (e4m3fnuz on gfx942, OCP e4m3 on gfx950); the quantisation maximum (224, 240 or 448) is stated per row.
- CU count: `torch.cuda.get_device_properties(0).multi_processor_count`. Every split rule here reads it.
- KV cache dtype: `cache_config.cache_dtype` (`--kv-cache-dtype`); model dtype: `model_config.dtype`.
- Env of the serving process: `VLLM_ROCM_USE_AITER`, `VLLM_ROCM_USE_AITER_FP8BMM`, `VLLM_ROCM_USE_AITER_FP4BMM`,
  `VLLM_ROCM_USE_AITER_TRITON_SPARSE_MLA`, `VLLM_BATCH_INVARIANT`.
- Compile mode: `compilation_config.cudagraph_mode` (a full decode graph pins the `TRITON_MLA` split count at 1: MLA-17).
- Live layout: `kv_cache.stride()`, `block_table.stride(0)`, `W_UK_T.stride()`, `W_UV.stride()` of the loaded layer.
- Model constants: `kv_lora_rank`, softmax scale, `index_topk`, index head dim, compress ratio, sliding window,
  `max_model_len`, sparse block size and top-k blocks.

| id | Fact | Applies to | Status | Effect if wrong | Source |
|---|---|---|---|---|---|
| MLA-01 | The layer writes the current token's latent and RoPE key into the cache (`concat_and_cache_mla`) in the same forward, right before the decode attention; a padding row (slot -1) writes nothing. | MLA-02 | One cache tensor `[blocks, block_size, kv_lora_rank + rope_dim]` (one KV head): latent in `[..., :kv_lora_rank]`, RoPE key right after it. | MLA-03 | Same tensor, but the AITER decode views it as page size 1 (`[rows, 1, 1, kv_lora_rank + rope_dim]`) and the metadata builder expands the block table (any block size) into per-token indices: position p is row `block_table[row, p // block_size] * block_size + p % block_size`. | vLLM · `ROCM_AITER_MLA` | source only | As MLA-02 | `vllm/v1/attention/backends/mla/rocm_aiter_mla.py:514-519, 1610-1640`; `vllm/_aiter_ops.py:775-784` (`_rocm_aiter_mla_decode_fwd_impl`) |
| MLA-04 | An fp8 cache (`fp8`, `fp8_e4m3`; AITER MLA also takes `fp8_e5m2`) is viewed as the platform fp8 type for the decode: e4m3fnuz on gfx942, OCP e4m3 on gfx950. ## Token-granular sparse MLA: indexer and top-k

An index output is a set. Compare selections as sets: two candidates may trade places only when their scores are equal
or within a rounding band of each other. The checks behind this file used the band `c * u * A` (u = fp32 unit roundoff,
A = the sum of absolute products behind the score, `c = 8 * sqrt(D) + H + 2` for a ReLU-weighted sum over H heads of
dimension D, `8 * sqrt(D) + 2` for a block maximum). A wrong switch changes the set only on rows with more candidates
than k, so short contexts cannot show it.

## Not covered by any check

- Any fp8 MLA cache: every fp8-cache row of `TRITON_MLA` and `ROCM_AITER_MLA` is `source only`, and the AITER
  fp8-query decode (fp8 x fp8 in the asm kernel) is not described at all.
- The tile, numerator rounding and split boundaries of the AITER asm decode (MLA-20, MLA-21): never measured.
- `ROCM_AITER_MLA` branches other than asm (gluon on gfx950, decode context parallel), and decode context parallel
  on any backend (partial outputs merged by LSE across ranks).
- Speculative verify blocks (more than one query token per request), on every backend of this file.
- The AITER fp8 / fp4 batched GEMMs for `W_UK` / `W_UV` (MLA-09 only states that they are off by default).
- `TRITON_MLA` with one query head per rank (MHA kernel), and its split count under a live CUDA graph (MLA-17).
- aiter's Triton sparse MLA (`VLLM_ROCM_USE_AITER_TRITON_SPARSE_MLA`, gfx950).
- The sparse indexer on gfx950 without AITER (a torch fallback that reads a block-flat cache while the writer emits
  the shuffled layout), and index caches whose block size is not a multiple of 16.
- gfx950 for the compressed sparse-latent rows (448 maxima, [0, 254] exponent clamp, fp8 output projection), an MXFP4
  indexer cache, and the kernel's amax floor in MLA-40.
- Order and exact-tie behaviour of the two radix top-k kernels (MLA-38, MLA-63): unspecified by the kernels and not
  characterised by any run.
- Block-sparse attention as a whole on a served model; in addition its fp8 main cache, the aiter paged path, MSA,
  the context-parallel indexer and score types other than the block maximum.
