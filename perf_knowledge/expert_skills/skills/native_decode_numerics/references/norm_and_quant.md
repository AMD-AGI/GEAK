# RMSNorm, fused norm + quant and residual mixing: native numerics facts

Covers the vLLM ROCm paths for RMSNorm and fused add + RMSNorm (one IR op, three providers that round at
different points), the fused RMSNorm + fp8 group quant that the compile passes insert, the gain-centred norm and
gated-residual kernels of a post-norm MoE model, and the multi-stream residual mixing ("hyper-connection") op.
Not here: SGLang's norm path and what was read of aiter's own RMSNorm kernel (`sglang_backends.md`), the fused
all-reduce + RMSNorm (`tp_allreduce.md`), the activation quant of a linear that is not fused with a norm
(`linear_and_gemv.md`).

**Versions.** Line numbers are valid at vLLM commit `f09d5e30c`, aiter tag `v0.1.26` (rows marked
`@285579b6` were read at that aiter commit) and, for SGLang, commit `22e1cb6d98`; in any other version
locate the code by symbol.

**Status.** `capture` = verified on a model capture (a captured decode step of a served model was reproduced
with this fact; "2 models" when two served models agree). `probe` = verified by a real-op probe (the installed
native op was run on synthetic inputs and compared with an emulation of this fact, usually bit for bit).
`source only` = read from source, never run against the native op: treat it as a suspect and confirm it with
the flip test in `parity_method.md` before relying on it.

**Model-package tags.** Resolve a tag by listing `vllm/models/` in the checkout.
- `<PKG_POSTNORM_MOE>` = the package of the post-norm MoE model with fused norm / routing kernels (contains
  `common/ops/fused_rmsnorm.py`).
- `<PKG_LATENT_SPARSE>` = the package of the sparse-latent-attention generation these rows were read in: of the
  two packages that contain `sparse_mla.py` and `compressor.py`, the one that also contains
  `common/ops/fused_indexer_q.py`. For `DeepSeek-V4.1` (the other of the two, with `amd/ops/sparse_indexer.py`),
  check that the same symbol exists in its own package before relying on a row; until then the row is
  `source only` for it.

**Effect sizes.** "x tol" is a multiple of the operator's derived tolerance (`parity_method.md`), measured by
flipping one switch in an emulation on synthetic shapes: an order of magnitude, not a promise for your shape.
"Invisible at stage level" means the wrong value stays inside the tolerance, so an operator-level comparison
passes with the wrong arithmetic and only a bit-exact comparison against the native op shows it.

## Which backend is running

Identify the provider of the process that produced the reference outputs you are compared against, not of the
production deployment: an eager capture process logs `['vllm_c', 'native']` even when production compiles and
replays CUDA graphs. If the task's oracle calls a native op directly, that call is the provider.

## Rounding points at a glance

| Path | Residual sum or blend | Normalised value before the weight | Stores | Rows |
|---|---|---|---|---|
| IR `native`, bf16 weight | fp32; returned residual is a rounded copy, the variance reads the fp32 sum | rounded to bf16 | product rounded again: two roundings | NRM-04, NRM-08 |
| IR `native`, fp32 weight (unit-offset norm) | fp32, as above | not rounded | one rounding | NRM-06 |
| IR `vllm_c` | rounded to bf16 first; the variance reads the rounded sum | not rounded | one rounding | NRM-05, NRM-09 |
| aiter fused norm + quant | fp32, variance over the fp32 sum | not rounded | fp32 value quantised directly; max 240 (FNUZ), amax floor 1e-10, group 128 | NRM-17, NRM-18 |
| vLLM C fused norm + quant | fp32, variance over the fp32 sum | rounded to bf16 | product rounded to bf16, then quantised; max 224 (FNUZ), amax floor 1/512, group 64 or 128 | NRM-19, NRM-20 |
| Gain-centred Triton norm | fp32 blend `alpha * stream + beta * y` with the fp32 `y` | not rounded | one rounding, in the call's output dtype (the stream is usually fp32) | NRM-22, NRM-29 |
| Hyper-connection fused op, gfx942 | fp32; the mixes and the variance read the fp32 values | not rounded | both bf16 stores truncate | NRM-39 to NRM-42 |

## Fused RMSNorm + fp8 group quant

The two fused ops are not interchangeable. aiter: maximum 240, amax floor 1e-10, the fp32 norm quantised
directly, group 128. vLLM C: maximum 224, amax floor 1/512, two bf16 roundings before the quant, group 64 or
128. (Maxima for e4m3fnuz; both use 448 on OCP fp8.) The scale output pins the numerics: it has a tight
tolerance, while the fp8 bytes are judged at one fp8 ulp and catch gross errors only.

## Gain-centred norm and gated residual (post-norm MoE model)

A post-norm MoE model whose package `<PKG_POSTNORM_MOE>` brings its own norm and residual-connection modules and
Triton kernels. The rules key on the module classes and their constructor arguments (weight or not,
zero-centred gamma, gain centre, stream gate, channel-wise gate), so any model built from these modules runs
the same kernels. Class names are given by their endings. All probes ran the real modules on synthetic shapes.

## Multi-stream residual mixing (hyper-connections)

A model with multi-stream residual mixing and sparse latent attention keeps `hc_mult` (4) residual streams
`[.., hc, H]` instead of one. Around every sub-layer one fused op (`MHCFusedPostPreOp`) does three things.
*Post* writes the previous sub-layer output `x` back into the streams: `r' = post_mix * x + comb^T r`. *Pre*
derives the next mixing weights from the streams (a small fp32 projection `fn`, an RMS scale, sigmoids and a
Sinkhorn-normalised `hc x hc` matrix) and collapses the streams into the next sub-layer's input,
`sum_h pre[h] * r'[h]`. Optionally the next sub-layer's RMSNorm is folded in. Outputs: new streams (bf16),
`post_mix` `[.., hc, 1]` and `comb_mix` `[.., hc, hc]` (fp32), layer input `[.., H]` (bf16).

These rows were read in `<PKG_LATENT_SPARSE>` and checked on captures of a model of the generation before
`DeepSeek-V4.1`. `DeepSeek-V4.1` belongs to the same family and has its own package: re-confirm each row there.

## Not covered by any check

- The `aiter` RMSNorm provider on the vLLM side: its rounding points were not read here. `sglang_backends.md`
  carries what was read (source only) of aiter's `rmsnorm2d_fwd` / `rmsnorm2d_fwd_with_add` through SGLang's call
  path; measure against the native op before relying on either.
- The priority branches other than eager: `native` under Inductor (the traced code's explicit casts should
  survive the compiler's fusion; not verified) and `aiter` first under CUDA graphs.
- `VLLM_BATCH_INVARIANT`, which routes RMSNorm to a different kernel, and a variance-size override (variance
  over a prefix of the row).
- Fused norm + quant on gfx950 (OCP fp8, maximum 448), column-major (transposed) scales, and whether a
  unit-offset norm ever fuses.
- Post-norm MoE model: the weight-before-norm class's `forward_native` (`F.rms_norm`), a gate whose coefficients
  are not materialised (recomputed on every call), stream and branch of different shapes (broadcast fallback),
  and a build where `flashinfer` is importable (CUDA only: the D = 8192 fp32-stream gated case then runs another
  kernel).
- Hyper-connections: gfx950 (round-to-nearest stores, and a gfx950-only delayed-norm path in vLLM), token counts
  at or above the fused bound, the TileLang and torch fallbacks, the separate pre / post / head ops, `hc_mult`
  other than 4, and `DeepSeek-V4.1` itself.
- Every `probe` row was run on gfx942 only.
