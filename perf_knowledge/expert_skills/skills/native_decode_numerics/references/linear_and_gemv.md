# Linear and GEMV: native numerics facts

vLLM's ROCm linears at decode: the block-scale fp8 linear (plain and with a preshuffled weight), the bf16
linear and its skinny GEMV kernels, the packed q / k / v (+ output gate) projection, and the act-and-mul
epilogue that a merged gate / up projection feeds. Not here: MoE expert GEMMs (`moe_and_routing.md`) and
SGLang's linears (`sglang_backends.md`). "Effect if wrong" is the error of the wrong choice against a reference
with the right one, as a multiple of the stage tolerance on synthetic inputs: an order of magnitude, not a bound.

**Versions.** Line numbers are valid at vLLM commit `f09d5e30c`, aiter tag `v0.1.26` (rows marked
`@285579b6` were read at that aiter commit) and, for SGLang, commit `22e1cb6d98`; in any other version
locate the code by symbol.

**Status.** `capture` = verified on a model capture (a captured decode step of a served model was reproduced
with this fact; "2 models" when two served models agree). `probe` = verified by a real-op probe (the installed
native op was run on synthetic inputs and compared with an emulation of this fact, usually bit for bit).
`source only` = read from source, never run against the native op: treat it as a suspect and confirm it with
the flip test in `parity_method.md` before relying on it.

**Model-package tags.** `<PKG_LATENT_SPARSE>` = the package of the sparse-latent-attention generation these
rows were read in: of the two packages that contain `sparse_mla.py` and `compressor.py`, the one that also
contains `common/ops/fused_indexer_q.py`. `DeepSeek-V4.1` belongs to the same family but has its own package:
check that the same symbol exists there before relying on a row; until then the row is `source only` for it.
`<PKG_POSTNORM_MOE>` = the package of the post-norm MoE model with fused norm / routing kernels (contains
`common/ops/fused_rmsnorm.py`). Resolve a tag by listing `vllm/models/` in the checkout.

- Which of the three activation quant kernels ran on the captured models: each kernel's arithmetic is probed
  (LIN-16, LIN-18, LIN-19), the selection between them is source only.
- The accumulation order of the compiled GEMMs (CK block-scale, the tuned preshuffled variants, hipBLASLt for
  more than 5 tokens) and any split-K inside them.
- A bias on a block-fp8 linear, a bias of another dtype than bf16, and where hipBLASLt, aiter `tgemm` and the
  aiter Triton GEMM add a bias.

  device's CU count) were read, never run.
- `VLLM_BATCH_INVARIANT` (it forces other kernels) and an fp16 output dtype.
- The erf GELU fallback of the native `GeluAndMul` forward, and the clamped SiLU op with alpha ≠ 1 or
  beta ≠ 0 (it runs the native forward, whose rounding points are not described here).
- An act-and-mul whose custom-op state was not recorded: read the `custom_ops` list, never guess (LIN-06).
- Both packed q / k / v / gate layouts on a real checkpoint, and any quantised packed projection (LIN-29).
- The preshuffled rows (LIN-09 to LIN-13, LIN-17, LIN-22, LIN-35 to LIN-37) on any other model of that
